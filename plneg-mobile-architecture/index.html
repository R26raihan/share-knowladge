1. Overview

EGIS (iOffice PLN EG) adalah aplikasi mobile enterprise untuk PLN Enjiniring (PLN EG) berbasis Flutter, mencakup absensi (face detection + geofencing), persuratan/disposisi, pengajuan operasional kerja (iMeeting, iTransport, iSPPD), dan manajemen kepegawaian (SK, cuti, slip gaji). EGIS adalah hasil rombak dari project BAG sebelumnya — fiturnya kurang lebih sama, sehingga sebagian kode lama (termasuk modul enkripsi) masih terbawa meski belum dipakai di flow saat ini (lihat §5).

Platform: Android & iOS. Flutter SDK ^3.8.0. Package aplikasi: EGIS.

2. Layer arsitektur (Clean Architecture)

Struktur lib/ dipisah modular per tanggung jawab:

lib/
├── config/        # DI (GetIt), environment/flavor, router, theme
├── core/          # network (Dio + interceptor), security, storage, services
├── data/          # datasources (remote/local), models, mappers, repository impl
├── domain/        # entities, repository interface, use case (pure Dart)
└── presentation/  # bloc/cubit, screens, widgets, controllers, dialogs

Alur data satu arah: UI/Screen → BLoC Event → UseCase → Repository Interface → Repository Impl → DataSource (Remote/Local). Setiap use case mengembalikan Future<Either<Failure, T>> (dartz); kegagalan ditangkap sebagai subtype Failure (ServerFailure, CacheFailure, NetworkFailure).

Repository implementation memilih antara remote data source (API) dan local data source (cache), sehingga domain layer tidak tahu sumber datanya dari mana — ini yang membuat use case tetap pure Dart dan mudah diuji.

3. State management & DI

  • State management: flutter_bloc (BLoC/Cubit per fitur — ada 40+ BLoC di presentation/bloc/, satu per use case screen: attendance, imeeting, isppd, itransport, salary, sk_kepegawaian, dll).
  • Dependency Injection: get_it — satu service locator global (config/di/injector.dart) mendaftarkan DioClient, API factory, data source, repository, dan use case untuk setiap fitur.
  • Functional error handling: dartz (Either<Failure, Success>) dipakai konsisten di semua use case & repository.

4. Jaringan & Dio Client

Semua request HTTP lewat satu DioClient (core/network/dio_client.dart) dengan API module per fitur di core/network/api/ (auth, attendance, imeeting, isppd, itransport, salary, sk_kepegawaian, dashboard, notification, approval, dll).

Interceptor Dio menangani:

  1. Auto-attach token: membaca auth_token/sso_jwt_token dari SharedPreferences, mengecualikan endpoint publik (login, checkpass, checkotp, forgot-password, dll).
  2. Auto-refresh JWT: jika token mendekati/sudah expired (exp klaim JWT), request di-pause untuk refresh token lebih dulu (dengan Completer untuk mencegah refresh ganda saat request paralel).
  3. Auto-logout: jika respons 401/"token expired"/"session expired" dan refresh gagal, aplikasi membersihkan sesi lokal dan navigasi paksa ke halaman login (route loginsso — nama lama dari BAG, isinya login email/password biasa).
  4. Observability: integrasi alice/talker_flutter untuk inspeksi request/response saat development, plus pelaporan error API ke Firestore (DebugReportingService) untuk debugging jarak jauh.

5. Autentikasi

Login saat ini email/password polos ke Odoo — POST /api/v1/auth/login (AuthApi.loginOdoo), tanpa SSO Microsoft, tanpa enkripsi payload, tanpa MFA/TOTP. Setiap login mengirim device_id, device_name, platform, dan fcm_token untuk keperluan push notification, bukan untuk validasi sesi multi-device.

  • Token: access token JWT + refresh token. DioClient otomatis refresh token yang mendekati/sudah expired dan auto-logout saat server membalas 401/"session expired" (lihat §4).
  • Lupa password: alur forgot-password → verify-otp → reset-password via email, bukan TOTP authenticator.
  • Device hardening: deteksi jailbreak/root (flutter_jailbreak_detection), biometrik lokal (local_auth), dan deteksi fake/mock GPS (detect_fake_location) untuk melindungi absensi — ini aktif dipakai.
  • Kode peninggalan BAG (belum dipakai): EncryptionService (RSA + AES-256-CBC, core/services/encryption_service.dart) di-inject ke AuthRemoteDataSourceImpl tapi parameternya dibuang begitu saja (: _authApi = authApi;) — tidak ada method enkripsinya yang pernah dipanggil di flow login. Interceptor Dio juga masih menyisakan path /svc-mobile/auth/me & /svc-mobile/totp dan key sso_jwt_token dari desain SSO/MFA BAG yang lama, tapi tidak ada screen/BLoC yang memicunya di EGIS. Kalau SSO Microsoft + MFA mau diaktifkan lagi, rancangannya ada di panduan SSO Microsoft 365 + MFA — tapi itu masih rancangan terpisah, bukan deskripsi kode EGIS saat ini.

7. Firebase & notifikasi

  • FCM (firebase_messaging + flutter_local_notifications) untuk push notification, dengan handler foreground (FcmService) dan navigasi berbasis payload (FcmNavigationHandler).
  • Crashlytics: menangkap fatal error framework dan error async yang tidak tertangani.
  • Remote Config: fetch konfigurasi dengan fallback lokal saat app start.
  • Performance & Firestore: monitoring performa dan (secara terbatas) pelaporan debug token/error API.
